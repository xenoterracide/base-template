# Template Repo Design

Status: Accepted (superseded in part — see Deviations)

Date: 2026-09-07

## Purpose

Repurpose the `base-template` repository (formerly the "share" tooling repo,
consumed via git subtree/submodule) into a **copier project template** with two
variants — Java and TypeScript — that serve as the **convergence target** for
the existing ecosystem of repos. Generated projects converge onto one shared
source of truth for tooling; template changes propagate to downstream repos via
automated PRs.

Existing repos that converge onto this template:

- `xenoterracide/java-commons` (Java multi-module Maven, Apache-2.0 today)
- `xenoterracide/ghb` (TypeScript monorepo, GPL-3.0-or-later today)
- `xenoterracide/agent-skills` (config/tooling-only repo, no packages)

The template is a convergence target, not a mirror: generated projects start
tighter and more uniform than today's repos, and existing repos move toward it
via `copier update`.

## Decisions

Recorded during brainstorming:

- **Approach A**: single flat template at the repo root. No `_subdirectory`.
  Variant-only files use conditional filenames/directories
  (`{% if template_type == 'java' %}pom.xml{% endif %}.jinja`). Shared content
  duplicated zero times.
- **License is parameterized** per generated project (GPL-3.0-or-later /
  Apache-2.0 / MIT), driving SPDX headers, `LICENSES/*.txt`, `.lintstagedrc`
  code tier, `pom.xml`, and `package.json`.
- **Java build tool**: Maven parent POM + wrapper (`mvnw`), multi-module with a
  first `module/` skeleton.
- **TypeScript**: yarn workspaces monorepo with a first `packages/` skeleton.
  Yarn PnP like existing repos.
- **Repository shape**: always the code/monorepo shape. No "config-only" prompt.
  Config-only consumers (e.g. agent-skills) delete the scaffold after
  generation; `copier update` is non-destructive to files not in the template,
  so this is a one-dir + one-line cleanup.
- **Update mechanism**: copier renders full files into generated projects
  (no subtree/submodule). `.copier-answers.yml` is committed so projects can
  `copier update`.
- **Git hooks**: rich set from this repo deployed into every generated project:
  `pre-commit`, `commit-msg`, `post-checkout`, `post-merge`, `sync-tooling`,
  `check-yarn-env`.
- **CI for generated projects**: reusable workflows from `xenoterracide/github`
  (license, prettier, maven, yarn, shellcheck), refs pinned to exact versions
  or commit SHAs. Authored into `staged/` (see Workflow staging).
- **Downstream updates**: push-based job in this repo that runs `copier update`
  on each downstream repo, opens PRs, relies on downstream CI to catch bugs.
  Auto-merge is a toggle, gated on a usable PAT.
- **Template self-testing**: uv/pytest that renders each variant into a tmpdir
  and asserts structure + checks pass, run in this repo's CI.
- **Dep-set / baseline version ownership**: template owns the dependency set and
  baseline ranges (declared once in `package.json.jinja`); downstream renovate
  owns within-range bumps. A dep-set change in the template propagates through
  the downstream-update job; `copier update`'s 3-way merge preserves local
  renovate bumps except on genuine conflicts (emitted inline/rej for manual
  resolution).
- **Post-copy tasks**: a prettier `_task` runs in the destination on every
  copy/update (requires `--trust` for URL-cloned templates). REUSE/SPDX headers
  are baked into `.jinja` sources rather than applied by an annotate task.
- **Workflow staging**: the agent's token and the downstream-update PAT lack the
  `workflow` scope, so pushes that create/modify `.github/workflows/**` are
  rejected. All workflow files this template authors are instead written under a
  staged directory in the generated project; a human moves them into
  `.github/workflows/` on their account with scoped credentials.

## Template structure

Single flat template at the repo root.

```
base-template/
  copier.yml
  .copier-answers.yml            # generated by copier in destination (never authored)
  git/hooks/*                    # verbatim: pre-commit, commit-msg, post-checkout,
                                 #   post-merge, sync-tooling, check-yarn-env
  .editorconfig                  # verbatim
  .gitattributes                 # verbatim
  .envrc                         # verbatim
  git-conventional-commits.yaml  # verbatim
  opencode.jsonc                 # verbatim
  .github/renovate.json5         # verbatim (canonical, from this repo)

  # rendered — shared by both variants
  package.json.jinja
  pyproject.toml.jinja
  .tool-versions.jinja
  .lintstagedrc.cjs.jinja
  .prettierrc.cjs                # verbatim (static; plugins identical both variants)
  .prettierignore.jinja
  .gitignore.jinja
  REUSE.toml.jinja
  README.md.jinja
  AGENTS.md.jinja
  CONTRIBUTING.md.jinja
  # no LICENSES/ in the template — a post-copy task runs `reuse download --all`
  # to fetch EVERY referenced license text into each generated project (CC0,
  # CC-BY-NC-SA, MIT, plus the chosen project license), so consumers' LICENSES/
  # is deterministic and canonical

  # header sidecars for files that can't carry inline SPDX comments
  package.json.license.jinja
  {% if template_type == 'typescript' %}tsconfig.eslint.json.license{% endif %}.jinja

  # workflows — rendered, always into staged dir
  staged/.github/workflows/*.jinja

  # java-only (conditional filenames/dirs)
  {% if template_type == 'java' %}pom.xml{% endif %}.jinja
  {% if template_type == 'java' %}mvnw{% endif %}.jinja
  {% if template_type == 'java' %}mvnw.cmd{% endif %}.jinja
  {% if template_type == 'java' %}.mvn{% endif %}/jvm.config.jinja
  {% if template_type == 'java' %}.config{% endif %}/checkstyle/main.xml.jinja
  {% if template_type == 'java' %}.config{% endif %}/checkstyle/test.xml.jinja
  {% if template_type == 'java' %}.config{% endif %}/spotbugs/exclude.xml.jinja
  {% if template_type == 'java' %}module{% endif %}/<name>/...  # first module skeleton

  # typescript-only (conditional filenames/dirs)
  {% if template_type == 'typescript' %}eslint.config{% endif %}.jinja
  {% if template_type == 'typescript' %}tsconfig.eslint.json{% endif %}.jinja
  {% if template_type == 'typescript' %}vitest.config{% endif %}.jinja
  {% if template_type == 'typescript' %}packages{% endif %}/<name>/...  # first package skeleton
```

### Template repo is also a consumer-source (two hats)

This repo is simultaneously (a) the template being copied and (b) a repo with
its own authoring tooling. Files used only for authoring this repo must NOT be
copied into generated projects, and any file with a `.jinja` sibling rendering
to the same destination path would collide. `_exclude` handles both:

```yaml
_exclude:
  - .github/workflows # this repo's own CI (holes in it, staging coverage)
  - docs/ # design docs, not for consumers
  - tests/ # template self-tests, not for consumers
  - package.json # authoring devDeps; consumers get package.json.jinja
  - pyproject.toml # authoring uv deps; consumers get pyproject.toml.jinja
  - yarn.lock # consumers generate their own after first install
  - uv.lock
  - .tool-versions # authors use one; consumers get .tool-versions.jinja
  - .python-version
  - .lintstagedrc.cjs # authoring copy; consumers get .lintstagedrc.cjs.jinja
  - LICENSES # this repo's own compliance texts (GPL/CC0/CC-BY-NC-SA/MIT);
    # consumers get theirs via the reuse download task
  - .yarn/ # tooling artifacts
  - .pnp.*
  - node_modules
  - .venv
```

Adding a new authoring file means remembering it here — the spec's rule is:
**anything that is only authoring tooling for this repo gets an `_exclude`
entry; anything that is genuinely shared, verbatim config stays as a copied
file**. Verbatim shared files (hooks, `.editorconfig`, `.prettierrc.cjs`,
`renovate.json5`) serve both hats without conflict because there is no rendered
sibling. The `.jinja` sources do not need excluding — copier renders them and
strips the suffix.

### Shared-file principle

Anything byte-identical across all generated projects is a **verbatim** file
(no `.jinja` suffix): hooks, `.editorconfig`, `.gitattributes`, `.envrc`,
`git-conventional-commits.yaml`, `opencode.jsonc`, `.github/renovate.json5`,
`.prettierrc.cjs`. Only files that vary by answer or variant get `.jinja`.
Shared files that currently drift between java-commons and ghb
(`renovate.json5`, `.lintstagedrc.cjs`, workflows) exist once, here — this repo
is the canonical source.

Config source-of-truth notes:

- `renovate.json5` — canonical is **this repo's** copy (has `recreateWhen`,
  `newDigest` pinning; does NOT carry ghb's `typescript: <7` anomaly workaround
  or stale `ignorePaths` from java-commons).
- `.lintstagedrc.cjs` — canonical shape is java-commons' (adds the
  `*.properties` and separate `*.ts`/`*.java` rows, the yml comment); `licenseCode`
  is parametrized by the `license` answer.
- `.tool-versions` — java adds `java` + `ktlint`; otherwise `nodejs`, `python`,
  `shfmt`.

## copier.yml questions and settings

```yaml
template_type:
  type: str
  help: Which project template?
  choices:
    Java: java
    TypeScript: typescript
  default: typescript

project_name:
  type: str
  help: Repository slug (e.g. java-commons)

project_title:
  type: str
  default: "{{ project_name }}"
  help: Human-readable name for README/AGENTS

license:
  type: str
  choices:
    GPL-3.0-or-later: GPL-3.0-or-later
    Apache-2.0: Apache-2.0
    MIT: MIT
  default: GPL-3.0-or-later

copyright_holder:
  type: str
  default: Caleb Cushing

copyright_year:
  type: str
  default: "{{ '%Y' | strftime }}"
  # computed/locked: not re-asked, and pinned in the answers file
  # (do NOT use the deprecated now(); strftime is copier's recommended way)
  when: false

# java only
java_group_id:
  type: str
  default: com.xenoterracide
  when: "{{ template_type == 'java' }}"
java_module:
  type: str
  default: "{{ project_name }}"
  when: "{{ template_type == 'java' }}"
java_version:
  type: str
  default: 0.0.0
  when: "{{ template_type == 'java' }}"

# typescript only
ts_scope:
  type: str
  default: "@xenoterracide"
  when: "{{ template_type == 'typescript' }}"
first_package:
  type: str
  default: "{{ project_name }}"
  when: "{{ template_type == 'typescript' }}"
```

Settings:

- `_min_copier_version`: pin a floor (e.g. `4.0.0`)
- `_message_after_copy`: next steps — create repo, `yarn contribute`, run
  checks, copy `staged/.github/workflows` into place, delete scaffold if
  config-only
- `_templates_suffix`: leave at default `.jinja`
- No `_subdirectory` (Approach A)
- `_envops.undefined`: `jinja2.StrictUndefined` so typos surface at render time
- `_tasks`: post-copy commands in the destination, run on every copy/update, so
  they must be idempotent. Decision:
  1. `npx --yes prettier@3.6.2 --ignore-unknown --write .` — format every
     rendered file. Runs before `yarn install`, so it must not rely on
     node_modules — the pinned `npx` invocation (with node/npm on PATH) is
     self-contained. Idempotent: files already prettier-clean are unchanged.
  2. `uvx reuse download --all` — download the license texts the project
     references into `LICENSES/` (network-at-generation; runs fine in the
     downstream-update CI job). `--all` fetches only missing licenses, so
     updates are near no-ops.
     SPDX/REUSE headers are **baked into the `.jinja` sources** (deterministic, no
     dependency on `reuse` annotate at generation time, and immune to the still
     unmerged REUSE "replace" bug). Files that cannot carry inline headers
     (`package.json`, `tsconfig*.json`, etc.) get `.license` sidecar **`.jinja`**
     siblings. `reuse annotate` in the pre-commit lint-staged hook still applies to
     user-authored files at commit time; because generated files come with baked
     headers, annotate never re-touches them.
- External consumers and the downstream-update job MUST pass `--trust` for
  `_tasks` to run (local template runs are not gated). The downstream job uses
  `copier update --trust --defaults --conflict rej`.
- `_migrations` reserved for future structural migrations (not needed now).
- Provide `{{ _copier_conf.answers_file }}.jinja` (renders `.copier-answers.yml`)
  so computed/locked answers like `copyright_year` are pinned and survive
  `copier update` (see copier FAQ "computed values")

## Generated project layout (code shape)

### Java — `module/<java_module>/`

- Root: parent `pom.xml` (compiler release 21, Error Prone + NullAway, Checkstyle
  2-config, SpotBugs exclude filter, JaCoCo 90% instruction minimum, JUnit BOM,
  AssertJ, Vavr test scope), `mvnw`, `mvnw.cmd`, `.mvn/jvm.config`,
  `.config/checkstyle/{main,test}.xml`, `.config/spotbugs/exclude.xml`
- `module/<java_module>/`: module `pom.xml`, `src/main/java/module-info.java`
  (`@NullMarked`, JSpecify), package skeleton (`com.xenoterracide.<...>`),
  `src/test/java/` black-box structure + one smoke test
- `.gitignore` includes `target/`, `.mvn/` variants

### TypeScript — `packages/<first_package>/`

- Root: `package.json` with `workspaces: ["packages/*"]`, `eslint.config.cts`
  (typescript-eslint strictTypeChecked), `tsconfig.eslint.json`,
  `vitest.config.ts` project-based (ghb-style), `.prettierignore`
- `packages/<first_package>/`: `package.json` (`@xenoterracide/<first_package>`),
  `src/`, `test/`, `tsconfig.json`, `vitest.config.ts` with coverage thresholds
- `.gitignore` includes `dist/`, `coverage/`, `.pnp.*`

### Shared (both variants)

`contribute` script in every generated project:

    yarn install --immutable && uv sync --frozen && git config core.hooksPath git/hooks

`.envrc` runs `asdf install` and warns if hooks are not configured. All files
carry SPDX headers via `.lintstagedrc` REUSE tiers (code = `{{ license }}`,
config = CC0-1.0, docs = CC-BY-NC-SA-4.0, scripts = MIT).

## Git hooks (deployed verbatim)

Rich set, unchanged from this repo's `git/hooks/`:

- `pre-commit` — skip CI, `check-yarn-env`, `yarn lint-staged`
- `commit-msg` — skip CI, `yarn git-conventional-commits commit-msg-hook "$1"`
- `post-checkout` — skip CI, branch-only, `sync-tooling` with previous HEAD
- `post-merge` — skip CI, `sync-tooling` with `HEAD@{1}`
- `sync-tooling` — detect `.tool-versions`/`yarn.lock`/`uv.lock` changes,
  run `asdf install`/`yarn install --immutable`/`uv sync --frozen`
- `check-yarn-env` — verify yarn availability with asdf-aware diagnostics

## Workflow staging

- All workflow files authored by the template render into
  `staged/.github/workflows/` (mirrored structure), never directly into
  `.github/workflows/`.
- Generated projects get a `staged/` directory containing the workflows plus a
  short `staged/README` describing the copy step
  (`cp -r staged/.github/workflows .github/workflows`), performed by a human
  with `workflow` scope.
- YAML files outside `.github/workflows/` are NOT restricted by GitHub, so the
  downstream-update job and agent can push the staged dir freely.
- `staged/` stays visible to prettier/reuse (ordinary YAML), so staged workflows
  are formatted and licensed like any other; no renovate or prettier exclusion
  of `staged/` is needed.

### Referencing actions

No floating major tags. Every action is referenced by exact version today:

- `actions/checkout@v7.0.1`
- `actions/cache@v6.1.0`
- `asdf-vm/actions/install@v4.0.1`
- `xenoterracide/github/.github/workflows/<wf>.yml@<commit-sha> # develop`

Renovate manages xenoterracide/** workflow references via
`helpers:pinGitHubActionDigests` (which it handles). Non-org actions keep exact
`major.minor.patch` tags; renovate's github-actions manager can then bump them
concretely (it does not rewrite `@v7` → the latest patch reliably, so we don't
start with floating tags).

### Workflows generated (all into staged/)

- `pre-commit.yml` — license + prettier (reusable: `license.yml`, `prettier.yml`)
- `test.yml` / `build.yml` — variant-specific: java → `maven.yml`;
  typescript → `yarn.yml`; both → shellcheck job
- `devtools-regression.yml` — devtool regression jobs (reusable)
- `opencode.yml` — AI comment bot (optional flag `use_opencode`, default true)

## Downstream-update job

Live in this repo under `staged/.github/workflows/update-downstream.yml` (moved
into place by human). Push-triggered on `develop`, plus `workflow_dispatch`.

Matrix of downstream repos:

    xenoterracide/java-commons
    xenoterracide/ghb
    xenoterracide/agent-skills

Flow per repo:

1. Check out this repo at the pushed SHA (template source).
2. Check out downstream at `develop` into `consumer/` using
   `DOWNSTREAM_UPDATE_PAT`.
3. `copier update --trust --defaults --conflict rej consumer/` — the command
   takes only `[destination_path=.]`; the template source is read from the
   answers file (`_src_path`). In CI, first rewrite `_src_path` in the
   downstream `.copier-answers.yml` to point at the local template checkout
   (`$GITHUB_WORKSPACE/template`), run update, then restore the canonical
   repository URL (`_src_path` is persisted back as the template URL). Run via
   `uv tool run copier` or `uvx copier`; `--trust` required so the post-copy
   prettier `_task` runs.
4. If the working tree changed: commit to `copier/update` branch, push, open PR
   against `develop`. Skip otherwise (no empty-PR noise).
5. Optional auto-merge toggle: `gh pr merge --auto --squash` (requires
   `DOWNSTREAM_UPDATE_PAT` with workflow scope to push workflow edits; most
   updates won't touch `.github/workflows/`, so the PAT needs at least `repo`
   scope; auto-merge should only be enabled when the PAT has `workflow` scope
   AND downstream branch protection permits it).

Secrets needed:

- `DOWNSTREAM_UPDATE_PAT` — currently the stale PAT; document refresh. A GitHub
  App is the eventual replacement for the PAT (not built now).

Conflicts: `--conflict rej` writes unresolved hunks as `.rej` files visible in
the PR for review. Downstream CI runs on the opened PRs, which is the primary
safety net (catch bugs early before merge).

The job itself cannot create `.github/workflows/update-downstream.yml` in this
repo via push (workflow scope), hence staging; a human moves it into place.

## Template self-testing

uv-managed pytest suite in this repo (`tests/`) that:

- For each `{java, typescript}`:
  - `copier.copy` into a tmpdir non-interactively with fixture answers
  - assert expected files exist, no `.jinja` leaked to the destination, and
    variant-only files are correctly present/absent
  - run `yarn lint:prettier` and `yarn lint:reuse` in the generated project
  - java: `./mvnw -q validate`; typescript: `tsc --noEmit`
  - assert `staged/.github/workflows` has the expected workflows

CI workflow for this repo (`staged/.github/workflows/test-template.yml`) runs
the suite; also reuse `xenoterracide/github` devtool regressions
(prettier, lint-staged, git-conventional-commits, reuse) against the `.jinja`
sources.

## This repo changes

What changes in base-template itself:

- Add `copier.yml`, the `.jinja` tree, `git/hooks/` (already present),
  `staged/`, `tests/`, `docs/`. The repo's own `LICENSES/` stays for its own
  REUSE compliance (excluded from the copy — consumers get theirs via
  `reuse download`).
- Keep dev tooling (`.prettierrc.cjs`, `pyproject.toml` gains copier/pytest dev
  deps, `.tool-versions`, `REUSE.toml`) so the `.jinja` sources themselves are
  prettier + reuse clean
- Rewrite `README.md`, `AGENTS.md`, `CONTRIBUTING.md` for the new purpose
- Retire the `.share` consumption model (no subtree/submodule instructions)
- Do NOT self-apply the template to this repo now (defer; renders next to
  `.jinja` sources). Authoring this repo is distinct from consuming it.

Python dev deps to add: `copier`, `pytest`, `jinja2` (already a copier dep),
`pyyaml` for answers parsing.

## Template versioning

- Tag releases `vX.Y.Z` on `develop`; `.copier-answers.yml` in each project
  records `_commit`.
- The push-based downstream job triggers on every push to `develop`, so projects
  keep flowing even between tags.
- Document tagging cadence in `CONTRIBUTING.md`.

## Deviations (recorded 2026-11-04)

The 2026-11-04 design
(`2026-11-04-revive-source-of-truth-design.md`) supersedes this spec's
toolchain choices. Its plan records the execution rulings. Summary:

- yarn 4.18 became pnpm 12.16.1; `yarn.yml` no longer exists upstream.
- `git/hooks/` became `.config/git/hooks/` with `heal.sh`; `sync-tooling`
  and `check-yarn-env` were deleted.
- A `config` variant and an `include_skeleton` answer were added.
- The skeleton's test toolchain BOM ships in the parent pom; product
  dependencies stay local.
- GitHub's `${{ secrets.* }}` expressions collide with Jinja and need
  `{% raw %}` wrapping.
- The post-copy prettier task runs without plugins, so `.jinja` sources
  must render prettier-clean unaided.
- The opencode config and comment-bot workflow were removed on 2026-11-07;
  repos carry no opencode files.
